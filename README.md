# Amou Music · 局域网播放遥控器

在手机、平板或同一 WiFi 下的任意设备上，用浏览器控制这台电脑的**系统媒体会话**和**主输出音量**。

网易云、QQ 音乐、Spotify、浏览器播的视频……只要它在播，遥控器就能控制它——因为走的是 Windows 全局媒体键，而不是绑定某个播放器。

---

## 快速开始

双击 `start.bat`。首次运行会自动建虚拟环境并装依赖，之后直接启动。

控制台会打印手机要访问的地址：

    在手机浏览器打开:  http://192.168.x.x:8765

用手机连同一个 WiFi，浏览器输入这个地址即可。

## 停止

控制台窗口里按 `Ctrl+C`，或直接关掉窗口。

## 换端口

    start.bat --port 9000

## 能做什么

| 操作 | 说明 |
| --- | --- |
| 播放 / 暂停 | Windows 全局媒体键 `0xB3` |
| 曲名 / 歌手 / 专辑 | 网易云本地缓存（只读） |
| 封面 | `GET /api/cover?song_id=`，按曲目缓存 |
| 歌词 | 网易云本地缓存，两行窗口（当前行 + 下一行） |
| 上一首 / 下一首 | 全局媒体键 `0xB1` / `0xB0` |
| 音量调节 | 直接读写系统默认输出设备的音量，精确到 1% |
| 静音 | 读取真实静音状态，不是自己记的开关 |

音量滑块支持拖动，页面每 2 秒跟 PC 侧同步一次，所以在电脑上改音量，手机上的数字也会跟着变。

## 已知边界

- **只支持网易云音乐。** 曲名、歌手、专辑、封面和歌词读的是网易云的**本地缓存**
  （`Library/webdb.dat` / `Statics/index.dat` / `Temp/index.dat`，均以只读方式打开，
  不复制、不加锁）。这三个都是私有格式，网易云升级后可能失效；失效时 `metadata`
  退回 `null`，界面显示「全局系统音频会话」，**音量与播放控制不受影响**。
  接入其他播放器的位置是 `metadata.py` 的 `MetadataSource`，加一个子类即可，
  `device.py` 不需要改动。
- **为什么不用 SMTC。** 标准做法是读 Windows 的 SystemMediaTransportControls，
  但这台机器的 WinRT 运行时组件是残缺的：用 `Windows.Globalization.Calendar.Calendar`、
  `Windows.Storage.ApplicationData` 这类**必然存在**的类做对照实验，`RoGetActivationFactory`
  同样全部失败，且 `roapi.dll`、`api-ms-win-core-winrt-l1-1-0.dll` 在系统中并不存在。
  也就是说这不是「缺依赖库」，装任何包都救不回来。
- **播放位置是估算的。** 本地没有位置源（`playingCount.playDuration` 是累计播放量，
  不是游标），位置由播放起始时间推算：暂停时冻结、恢复后续算，**拖动进度条会造成
  漂移且无法自愈**，直到下次切歌重新对齐。歌词当前行的高亮即基于此值。
- **唱片坐在一块圆形毛玻璃上，玻璃与唱片几乎等大。** 早先是圆角**方形**封套，
  唱片缩在 66%，四角是死的半透明区域——唱片是圆的，方框纯属浪费，看起来像
  装了框的照片。现在玻璃板改成圆形、加了真正的 `backdrop-filter`，唱片放大到
  **96%**，只留约 2% 的玻璃边。**不能取 100%**：唱片会完全盖住玻璃，磨砂、
  内描边和边缘一起消失，「圆形毛玻璃」就不存在了。
  玻璃用**中性纯色**（浅色 `rgba(24,28,32,.26)` / 深色 `rgba(255,255,255,.10)`），
  不跟随强调色——它紧贴黑色唱片，染成强调色会像唱片后面透出一圈色晕。
- **唱片与玻璃板由一个令牌整体缩放。** `--art-scale`（当前 0.80）作用在**玻璃板**
  上即可：唱片（96%）和标签（70%）都是它的百分比，沟槽周期又是半径的百分比，
  整套唱片会作为一个整体缩小，内部所有比例自动保持。不需要分别调三个尺寸。
- **歌词逐行居中。** 居中的是**每一行**而不是歌词条：歌词条是被 `translateY`
  位移的整列，居中整列只会让它最长的一行居中，其余行仍然参差。
  另加 `text-wrap: balance`，让折行的长句两侧尽量匀齐。
- **封面是画碟（picture disc），不是替换胶片。** 封面直径为黑胶的 **72.7%**
  （70% vs 96% 玻璃板宽），两者同心、同相位旋转，所以黑胶及其沟槽**始终露出一圈**。
  这个比例自画碟设计起就没变过，放大唱片时按同比例缩放标签，不重新配比。
  早期版本让封面和黑胶同为 66%，并在有封面时把黑胶 `opacity: 0`——结果整张封面
  糊满框，黑胶完全消失，只剩一张浮在背景上的照片。无封面（或封面 404）时自然退回
  纯黑胶 + 绿色中心标。
- **胶面高光是两段对称亮弧，不是一段。** `conic-gradient` 原本只有 0–88° 一段亮弧、
  其余 272° 全黑，亮质量永远偏在一侧，无论转到哪个角度唱片都显得歪。改成两段
  180° 相对的亮弧后，图案以 180° 为周期，**每个瞬间**圆心两侧的亮度都是平衡的，
  而亮弧本身仍然让旋转可读。实测对侧亮度差从 25/255 降到 3/255 以内。
- **高度预算是耦合的，改一个必须改另一个。** 列宽上限和 `--chrome` 一起解
  `W + chrome(W) <= 100dvh`，所以它们是同一组系数的两种写法。任何改动歌词、
  音量区或传输键的高度后，都要**重新实测 (列宽, 非封面高度) 数据点重新拟合**，
  并复测 `document.body.scrollHeight - innerHeight`。
  目前歌词上边距带来的约 20px 增量没有重新拟合，而是作为余量由 `--art-scale`
  吸收——8 个尺寸实测溢出均为 0。要维持的不变量是「溢出恒为 0」；若歌词边距
  发生实质变化，需在同一轮里同时重测系数与 `--art-scale`。
  歌词从可变滚动区改成固定两行时，chrome 抬高了约 25px，旧模型
  (`0.8W + 198`) 漏算，实测在 560×900 / 720×1000 / 1280×720 / 1920×1080
  溢出 41–62px。重新拟合为 `0.86W + 231` 后，9 个尺寸里 8 个溢出归零。
- **圆盘的居中只由一处负责。** 样式表用 `inset:0; margin:auto` 定位，不写
  `transform`；GSAP 因此只需要动 `rotation`。早期版本在 CSS 里 `translate(-50%,-50%)`
  的同时又让 GSAP 设 `xPercent/yPercent:-50`，两条居中通道只要有一条不对齐就会漂。
  同理，**旋转元素上的投影必须径向对称**——带 `0 16px` 这种方向偏移的投影会跟着转，
  暗色质量每圈公转一次，看起来就像唱片在偏心打转，而实测圆心偏差是 0.00px。
- **长按歌词卡可展开全曲。** 默认仍是两行；**长按 420ms**（或聚焦后按
  Enter / 空格）把同一张卡展开成可滚动的毛玻璃板，最多 56dvh，并滚动到当前行。
  收起有三条路径：再次长按、点卡片以外任意处、按 `Esc`。
  - 移动超过 10px 会取消长按——拖动应当被当作滚动，而不是误开面板
  - 长按抬手后浏览器仍会补发一次 `click`，那一次会被吞掉，否则刚打开就立刻关闭
  - 收起时会把卡片的 `scrollTop` 显式归零：`overflow: hidden` 只是不显示滚动条，
    **并不禁止程序化滚动**，残留的 `scrollTop` 会把绝对定位的歌词条整体错位
    （实测残留 112px，收起后显示的两行会错）
  - 展开态上下边缘有渐隐遮罩：歌曲结尾时滚动已到顶，当前行无法被带到顶部而会
    被切成半行，渐隐让它读作「下面还有」而不是渲染故障
- **歌词与封面之间必须有间距。** 之前歌词条**完全贴着**封面（实测间距 0px），
  而它到下方曲名的间距却有 21-29px。上下不对称使歌词读起来像封面的一部分
  而非独立元素。现给歌词条加上 `clamp(15px, min(5.4cqi, 3.3dvh), 30px)` 上边距，
  与列内其它间距共用同一套双轴表达式。**上侧略大于下侧是刻意的**：歌词与曲名
  同为文字，间距小一点把它们归为一组，符合排版惯例。
- **歌词只显示两行：正在唱的和下一行。** 整份歌词**仍在 DOM 里**，卡片只是它的
  视口——屏幕阅读器仍能按顺序读完整首歌，视觉条和朗读内容不会脱节。
  英文歌词实测最长 55 字符，窄屏会折成两行；此时**当前行优先占满两行**，下一行被挤出
  视野，而不是把文字裁掉或加省略号。行高由单一变量 `--lyric-row` 决定，词条行
  （作词/作曲）因此改为只调透明度不缩字号——两套字号会让行高随当前行变化，窗口就会抖。
  **代价**：看不到后面的词了，需要完整歌词的曲目请另找歌词源。
- **卡片跟着网易云的存活走，与「有没有在出声」无关。** 早先的守卫是
  `if not playing and not player_running()`，于是用 VLC 播歌时 `playing` 为真、
  守卫自行关闭，网易云明明已经退出，屏幕上却还挂着它最后一首歌。
  现在只认进程存活：网易云不在，卡片就清掉。
- **播放器关闭后卡片会清空。** 判断依据是进程是否存活，而不是「有没有在出声」——
  暂停时播放器自己的「正在播放」栏仍然显示着封面，遥控器与之保持一致。
- **切歌后有 5 秒沿用上一首歌词。** 歌词归属没法用时间戳 join——`Temp` 的
  `time` 比 `historyTracks` 的 `playtime` 早 7.3–8.0 小时且偏移不固定，
  只能靠「条目变更检测 + 5 秒宽限」。宽限期内沿用旧词是为了不闪。
  宽限一满就是恒空，**不会回弹**：曾经为了「等迟到的歌词」把窗口重新计时，
  结果下一次轮询 elapsed 变小又落回宽限分支，旧词每 6 秒复活一次、整首歌
  不收敛。迟到歌词由「条目 id 变更」那条独立通道接住，不依赖任何时间窗。
  `python tools/verify-lyrics.py` 用确定性重放守着这两条。
- **没有媒体在播时**，按播放键 Windows 可能会改为启动你设置的默认音乐应用。这是系统行为，不是 bug。
- **播放状态图标只认白名单里的播放器。** 控制走全局媒体键，任何播放器都按得动；但「图标显示暂停还是播放」读的是音频会话图，而那张图是**全机器**的——语音助手、模拟器、游戏、通知，只要有一个在发声，早期的实现就会把图标永久锁在「暂停」。所以判定只统计白名单进程（网易云、QQ 音乐、酷狗、酷我、腾讯视频、VLC、Spotify、foobar2000、AIMP、MusicBee、Stify、Rhythmbox、Windows Media Player）。**要用别的播放器，往 `device.py` 的 `_MEDIA_PROCESSES` 里加一行进程名即可。** 漏加的后果只是那个播放器对遥控器不可见，不会让按钮显示错。
- **播放状态有几秒延迟。** 音频会话图不是即时的：实测暂停网易云后，会话对象要约 5 秒才消失（不是变成 Inactive）。前端因此做了双向去抖——连续两次读数一致才跟随，且按下时立即响应，所以不会来回跳。
- **音量只作用于系统默认输出设备**，不支持在多台设备间切换。
- **没有访问密码。** 这是刻意的选择：同一 WiFi 下的任何设备都能控制这台电脑。在咖啡厅或办公室这类公共网络下别开着。

## 防火墙

三个防火墙配置默认都是开的，不放行手机一定连不上。

- **以管理员身份运行** `start.bat`：程序会自动加一条 TCP 入站放行规则，重跑会自动更新。
- **普通权限运行**：控制台会打印一条可以直接复制粘贴的命令，需要管理员权限执行。

想撤销规则：

    netsh advfirewall firewall delete rule name="Amou Music Remote"

## 项目结构

    server.py        HTTP 层：路由、参数校验、启动横幅、防火墙
    device.py        设备层：音量/静音/媒体键，单工作线程串行化 COM 访问
    metadata.py      网易云本地缓存适配层（曲名/封面/歌词），可换播放器
    web/index.html   前端单文件（HTML+CSS+JS 完整内嵌），无构建步骤，不引用任何 CDN
    web/gsap.min.js  本地 vendor 的 GSAP 3.15.0（动效），由 server.py 白名单路由供给
    tools/           验证脚本（见下）；verify-api 与 verify-lyrics 都不需要浏览器
    start.bat        首次运行建 venv、装依赖、启动

## 验证

    pwsh -File tools/verify-disc.ps1

五组共 33 项。旋转圆盘的视觉居中是最早的目标，但只测它会测的东西没有意义，
所以现在也钉死了比例、歌词窗口、触控热区和整页高度预算：

    pwsh -File tools/verify-api.ps1      # 16 项，秒级，先跑这个
    python tools/verify-lyrics.py        #  2 项，歌词归属状态机
    pwsh -File tools/verify-disc.ps1     # 34 项，需要 Playwright CLI

**先跑 API。** 「画面对」和「能用」是两个独立的失败模式，视觉检查抓不到后者。
`d47f15c`（2026-09-27）把 `_read_state` 从模块函数重构成 `DeviceWorker` 方法时，
漏改了 4 个模块级 helper 的调用点 → `NameError` → **音量、静音、输出切换
全线 503，瘫了 3 天**，而这期间所有视觉检查全绿：按钮画得完全正确，
只是按下去没反应。`verify-api.ps1` 的第一版跑上去就直接抓到了那两个 503。

它用**幂等方式**测写操作——读出当前音量再写回同一个值，真正穿过设备层，
但不改变机器状态，`finally` 里恢复。负例也测：`{"value":"loud"}` 必须 400
而不是 500（500 说明校验被摘掉了，请求会一路走到设备层才炸）。

**测量前必须钉死视口，而且必须回读确认。** 脚本开头会 `kill` 旧会话、
重新 `open`、`resize` 到 1280×900，然后**断言 `innerWidth/innerHeight` 真的到位**，
不符就中止。不钉的后果是同一份页面一次量出 `sleeve 212x211px`、一次 `150x149px`
——不是页面变了，是会话保留了上次遗留的窗口尺寸。
**基线会动的几何断言不是断言；而「钉死基线」的代码自己也可能让基线悄悄跑偏。**

这条断言第一次运行就抓到了它自己：钉视口用的
`Invoke-Cli @('resize', "$RefW", "$RefH")` 里，最初写的是数组
`"$RefViewport[0]"`——**PowerShell 的双引号插值不解析数组下标**，
展开成 `"1280 900[0]"` 这样的垃圾参数，命令静默失败，视口压根没动。
所以 `RefW` / `RefH` 是标量不是数组，而且尺寸一律回读断言。

圆心偏差的容差 0.5px 来自实测分布（同尺寸下 0.16 / 0.27 / 0.31px）：
这个波动不是像素噪声（~870px 周长本该平均到百分之一像素），
而是封面图旋转中轻微失衡，属内容固有下限。原来的 1.0px 松到真实的
半像素回归能通过，中途试过的 0.3px 又在健康页面上 flaky。

**每条断言都必须反向验证过**，即故意把不变量改坏、确认脚本真的会红：

| 破坏手法 | 被谁抓到 | 退出码 |
| --- | --- | --- |
| 歌词 2 行 → 3 行 | 行高断言 + 360×640 溢出 5px | 1 |
| 封面 70% → 40% | `0.4 (want 0.70 +/-0.02)` | 1 |
| 玻璃板圆 → 方形 | `border-radius 12px` | 1 |

旋转圆盘的居中分两类，脚本两类都查：

- **几何**：把有圆盘的帧与「隐藏圆盘」的基线帧做差分，要求圆盘掩膜在每个旋转相位
  都是同一个大小的正圆，且圆心落在封套圆心上。健康值 ≤ 0.2px。
- **观感偏移**：圆盘明明居中，却因为**非对称投影随元素一起旋转**而看起来在公转。
  静态上要求旋转元素的所有 `box-shadow` 层 x/y 偏移必须为 0，动态上要求投影质心
  在各相位间漂移 < 6px。旧实现漂移 40px。
- **画碟结构**：封面与黑胶同心（偏差 < 0.5px）、同相位，且封面/黑胶直径比必须落在
  0.3–0.85 之间，同时黑胶 `opacity` 必须为 1——这三条任意一条被破坏，黑色沟槽就会
  重新被封面盖住。
- **高光对称**：沿可见胶环按角度分 72 个 bin 采样亮度，要求**对侧 bin 的平均亮度
  差 < 6/255**。单段亮弧实测 25/255，会被抓出来。注意这里必须比**每 bin 的均值**，
  不是像素总和——各 bin 像素数并不相等（抗锯齿、像素中心偏移），比总和等于在比
  人口而不是亮度。
- **钉死的比例**：玻璃板必须是 `border-radius: 50%`（方形框是画碟重构前的旧形态），
  封面标签 = 玻璃板的 70% ±0.02，封面/黑胶直径比落在 0.30–0.85，
  玻璃留边收窄到板宽的 1%–4%（实测 2.03%）。**黑胶不能取 100%**——
  那会盖住磨砂、内描边和边缘高光，「圆形毛玻璃」就不存在了。
- **高度预算**：8 个视口（360×640 到 1920×1080）逐一断言
  `document.body.scrollHeight - innerHeight <= 0`，外加歌词窗口高度
  ≈ 2 × 行高、逐行居中、传输键 ≥ 44pt。行高、面板、滑块任何一处改动
  长出滚动条，这里都会红。

脚本在失败时返回非零退出码，可直接接进 CI。前端改动无需重启服务（每次 GET 都重读
`index.html`），但改了 `device.py` / `metadata.py` / `server.py` 必须重启——模块已被缓存。

`device.py` 里所有碰 COM 的调用都被投递到一个专用工作线程。原因是 COM 必须按线程初始化，而且手机拖动音量滑块会产生一串密集请求，串行化能保证句柄一致。

## 环境

Windows 11 · Python 3.14 · 依赖只有 `pycaw`、`comtypes`、`psutil`，无 Web 框架。
网卡选择会自动跳过 VMware 和 Meta 的虚拟网卡，只用第一个物理地址。
接口地址不写死，控制台会按当前网卡现算。
